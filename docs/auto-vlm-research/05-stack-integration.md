# 05. Integration with the agent stack, and the spikes

> Design proposal; nothing is built. Facts about the agent stack are as of the `dgx-station-inference-stack` repository at `de5dd71` (2026-10-18, branch `feat/avo-dgx-endpoint`); facts about this repo are as of `origin/main` `9cb9e60b0` (2026-10-23). The owner may change the stack repo as autovlm needs. Back to the [index](README.md).

## 1. How agents launch today

All paths in this section are in the stack repo.

- **Launch.** `agent-dgx run <id> --agent <claude|codex|gemini|opencode|shell|pi|avo> --profile <p> [--endpoint upstream|dgx] [--model ID] [-- agent arguments]`, plus `--memory`, `--cpus`, `--mount` and `--gpu`. Text after `--` goes to the harness unchanged and may carry an opening prompt (`docs/operations/agent-dgx-sessions.md`, `stack/clients/agent_dgx/cli.py`).
- **A session** is the sandbox `agent-<id>`, the workspace `/agents/agent-<id>/workspace` (cloned from the invoking checkout and never re-seeded on attach) and the state directory `/agents/agent-<id>/state/<agent>`.
- **Model routing.** `--endpoint dgx` points Claude Code at the LiteLLM gateway and maps every model alias to the endpoint's model, because unmapped typed sub-agents are refused with 403 (`stack/clients/agent_dgx/adapters/claude_dgx.py`). `--endpoint upstream` keeps the harness's own provider.
- **Control.** herdr, a terminal pane manager, lists agents (`herdr agent list`), reports one agent's status (`idle`, `working`, `blocked`, `done` or `unknown`) and types a prompt into a running agent (`herdr agent prompt <id> <text>`). Launches run in a pane; there is no documented batch mode.
- **Network.** Sandboxes are microVMs with their own network stacks. Egress goes through the sbx proxy, which reaches the host's loopback on any port unless a rule denies it. The flagship is closed by the port-wide rule `sbx policy deny network '**:8000,**:8001'`, because rules match names and a name-specific rule leaks through aliases. The rules live in sbx's local state, not in the repo, and must be re-applied after `sbx policy reset`. No path between sandboxes is documented.
- **GPU.** The `agent-gpu` runner is a host daemon (its own user, rootless podman with CDI) reached at `127.0.0.1:18090` through the proxy. Session containers publish on `127.0.0.1:18100-18199`. The **40 GiB VRAM cap is global**, the sum across all sessions, with at most 8 live containers per session and 16 in total. One session cannot list or stop another's containers, but the design lists as an accepted risk that another sandbox can reach a session's published pool ports (`docs/superpowers/specs/2026-09-23-agent-gpu-runner-design.md`).
- **Mounts.** `--mount PATH[:ro|:rw]` takes absolute paths, with the destination equal to the source. Mounts are part of a session's immutable spec, so changing them means recreating the runtime.
- **Stall prevention.** A Stop hook blocks two known stall patterns. A watch, checking once a minute, pokes an idle agent with `herdr agent prompt`, but only when `/goal` is active and unmet. The watch is installed, disabled, and runs dry by default (`docs/superpowers/specs/2026-09-26-agent-stall-prevention-design.md`).

## 2. Changes autovlm needs in the stack repo

| Change                                    | Why                                                                                                                                                                                                                                       |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`agent-dgx run --autovlm <run>`**       | Like `--gpu`: mount the `autovlm` CLI, a per-session executor token and the train split's blinded inputs read-only (never select or holdout frames). Mounts are fixed at create time, so the launch must set them                         |
| **Port denies for worker sandboxes**      | Deny the `agent-gpu` pool range and every port but the executor's to autovlm worker sandboxes, closing the accepted pool-port risk for them. Because rules live in sbx state, the launcher must apply them, not a one-off command         |
| **A stall-watch trigger without `/goal`** | autovlm workers never set `/goal`. The watch should also act when the run's ledger shows an open brief, herdr reports the session idle, and the transcript has been quiet for a set time                                                  |
| **Fleet launch**                          | The manager launches N workers. Opening herdr panes per worker works with today's tools; a batch mode with no pane would be cleaner, and is optional                                                                                      |
| **A protected executor session**          | The executor needs its own `agent-gpu` session with a reserved share of the global 40 GiB, so other sessions cannot starve a search mid-epoch, and the reservation must protect the flagship's headroom as the current admission rules do |

## 4. Constraints that stay

- **autovlm never stops the flagship itself.** Fresh scenario batches render through synthbench's own GPU window, which stops the flagship and always restores it, under the owner's approval for generation runs. The workers run on the flagship, so **a render happens only between epochs, with the fleet drained**: the manager stops launching briefs, waits for every worker to return, requests the render, and starts the next epoch after the flagship is back.
- **The global VRAM cap stays global.** autovlm schedules inside it rather than raising it.
- **Sandboxes keep their current isolation.** autovlm adds narrower rules for its own sandboxes and widens nothing.
- **Synthbench storage rules hold.** Corpus and exports stay on the synthbench dataset, and sbx cannot mount paths under `/export`; any directory mounted into a worker sandbox must live elsewhere.
