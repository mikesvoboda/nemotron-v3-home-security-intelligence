# VSS Integration: State of the Stack

> **As of 2026-10-03, verified against `0d740944` (main after PR #6783) plus the register and gate commits stacked on it (tip `0a5414ca`).** This page is the maintained source of truth for the AI/VLM stack: what is **decided**, **measured**, **open** and **next**, plus the guardrails. What the stack **runs today** is described by [the current-state page](../architecture/ai-pipeline-current-state.md); this page restates only the code facts a reading depends on (section 2, each pinned), and that page quotes the P5a baseline in its section 5. [`AGENTS.md`](AGENTS.md) says how to work here. The 2026-09-23 README and AGENTS are kept verbatim in [`21-entry-pages-record-2026-09-23.md`](21-entry-pages-record-2026-09-23.md) and are never the answer to "what is true now".
>
> Every row in sections 2, 3, 4 and 7 carries its source; the queue in section 5 is 17 section 4, and each section 8 row is read from that doc's own head. A claim is **[O]** only when a durable source records the owner saying it; a commit message, a handoff or a note is **[A]**. The `<!-- pin -->` and `<!-- known-false -->` comments are checked by `scripts/check-vss-docs-currency.py`, so a code fact that moves, or a stale quote that disappears, fails loudly. The precedence rule (section 1), the Next five (section 5) and the document map (section 8) are agent-authored proposals (2026-10-03, **[A]**) until the owner ratifies them.

The effort began as research on replacing a home-security product's AI pipeline with NVIDIA's Video Search and Summarization (VSS) pipeline for consumer GPUs, and settled on adopting VSS's alert-verification pattern alone. A detector gates each upload, and **one vision-language model** verifies and risk-scores a batch's one to four key stills in a single constrained call (`vlm_assess`). That pattern is in main as the only per-event path (`ai-vlm` starts only under the compose profile `vlm`); it has not been accepted.

## 6. Guardrails and stop-and-ask

- **Test first.** A step closes on an executed command, its result and a commit, never on written code. Every claim carries an evidence marker. Read a directory's `AGENTS.md` before changing it.
- **Run the commands CI runs,** not a proxy: mypy over `backend/` and `synthbench/`, the suppression census with its baseline, the integration shards the diff touches. Never bypass the hooks (no `--no-verify`); where none are installed, as in the agent sandboxes, run `uvx pre-commit run --files <changed files>` and the `commit-msg` stage yourself before each commit. A green unit, contract and root-scripts run plus ruff did not catch four reds on PR #6783: mypy, the suppression census, the WebSocket contract test and its integration aggregate (ledger row 'VLM-PATH MEASUREMENT AND CLEANUP (2026-10-03)', first CI-read addendum; the census cause is ISS-088).
- **A carried number is a claim.** Measure it where you cite it, at the tip you cite it from. Do not read a change in CI check-run count between tips as a regression: path filters decide which workflows fire. Read check-runs with `gh api --paginate` and slurp the pages (`jq -s`).
- **The ledger is append-only.** A correction arrives as a new dated addendum. Cite a row by its heading and commit, never its number: rows renumber on merge.
- **Owner-held, bring the evidence and stop:** any change to a D or S line or a bar (a spec revision); go-live sign-off; Brev spend and the matrix run; whether a declared-truth, ideal-detector replay counts as the real corpus for the S2 and S3 verdicts and flip condition (iii) (OD-4); the `dgx-inference` stack (restarting the flagship vLLM, making the Cosmos stop permanent, changing LiteLLM routes); an `agent-gpu` refusal or a VRAM squeeze; whether to add a text LLM back (R10, E117); anything in doc 12; acceptance blanks on the main-green census; secrets, the Linear key, Dependabot policy and the smoke and ZAP rulings.
- **`.trivyignore` is an owner-review file.** An entry is dated (`REVIEW BY` 3-6 months out, checked by `scripts/check-trivyignore-expiry.sh`), evidenced and flagged to the owner in the PR, never silent. The one entry added on 2026-10-03 (`CVE-2026-93687`, review 2027-01-03) followed the owner's direction for that one finding; ask before adding another.
- **Push, PR and merge need the owner's go-ahead.** Three layers say so: the brief, the ledger's dated amendments (2026-09-25: push `feat/vss-gaming-gpu-profile` after each committed Phase 1 task; PRs and merges still need the go-ahead) and the user's own instruction in the session. The 2026-10-01 delegation ("you have authority to merge PRs as needed") covers merging only; the ledger records it as exercised only on an observed-green gate, which is the agent's practice, not the owner's words.
- **Measure on one build.** Compare models only on one llama.cpp build, and name each arm's quantization, which moves answers about as much as the build does (ISS-087); label every run's conditions (build and cache flags, weights hash, prompt, sampling, commit) and any skipped guard (`renderer_check: SKIPPED`).
- **State a claim's scope.** The 450 sets score declared truth with an ideal detector. Never quote a rate from one corpus or condition against another, report refusals beside the rate, and never quote an unrecorded result as measured.
- **Guard tests a verdict-path change must keep green** (the gateway model-set compose test, the legacy-branch deletion guard, the AI-contract check) are listed in [the current-state page](../architecture/ai-pipeline-current-state.md).
- **Synthbench exit codes:** 0 done, 1 your request needs fixing, 2 stop and ask the owner. On 2, do not retry, work around it or change library code; send the owner the command and its full message and wait. A message starting `unexpected error`, or a traceback, is a stop-and-ask whatever the exit code. `synthbench replay` cannot read the renderer unit from the `agent-gpu` sandbox, so it exits 2; the 2026-10-03 runs bypassed that one check on the owner's direction, only with the VLM in a fenced `agent-gpu` container and every `run.json` labelled `renderer_check: SKIPPED` (ledger row 'VLM-PATH MEASUREMENT AND CLEANUP (2026-10-03)'; OD-23, ISS-079); no other check and no other exit 2 is covered.
- **GPU:** only through `agent-gpu`, never around it. The flagship vLLM stays resident and the `dgx-inference` stack is the owner's: never touch it. Check free memory before loading a model (`nvidia-smi` on a host, `agent-gpu status` in the sandbox); the renderer shares the GB300 (E119). Serve one candidate at a time with an honest `--vram` and `agent-gpu rm` when done; one that does not fit under the broker cap is blocked, not squeezed.
- **Real-camera data never enters git.** Only synthetic items and aggregate metrics are committed; real-camera data lives only in the off-repo eval store (owner machines or Brev VMs, moved over SSH), and the eval store is wiped from a Brev VM at teardown (D10).
- **Docs 00-15 and 18-21 are a frozen record.** A correction is a dated errata entry appended to 16 plus a known-false row below; the original text stays (a dated banner above it where the gate requires one). README, AGENTS and 17 are edited in place: fix a status, count or typo directly and correct a published issue with a dated note under its block. The registry is in this repo only: nothing is filed on GitHub or Linear. Ids come from `scripts/vss-next-id.py` and are never renumbered; a collision takes a lettered suffix.
- **Stale instructions, do not follow:** the kickoff prompt in doc 13 would restart a finished program (E116); "retired code stays until R8" and "build empty states, not deletions" are false because R8 ran (E115). The live guardrail is the deletion guard: shipped code may not compare against the retired mode string. Doc 13's working rules (test first, evidence-closed milestones) still hold.
