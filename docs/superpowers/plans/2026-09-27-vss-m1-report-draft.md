## 2. The M1 code review, and what it found

The review is this workstream's built-in code review (the goal file retires `superpowers:`/`codex` here), run over the Phase 1 vlm path and turned into **seven commits** (`c8050bac` … `13f2d65e`), each red-first, each gated, all pushed. Full evidence is the ledger's "M1 review" row; the finding classes:

1. **Provenance had readers that ignored the belt** (`c8050bac`, 6 sites) — a face gallery whose foreign-space row was the byte-better match reported a _match_; the client-vector face endpoint was still in service (now 410, the D-1 precedent).
2. **The null-lie lived on surfaces 1.6 did not name** (`4bc16ebe`) — `utils/risk.ts`'s null-safe helpers had shipped with **zero production adopters**, so D11 was enforced only in its own unit tests while `DashboardPage`'s `?? 0` made the P0.25 gauge guard dead code for every REST event.
3. **The vlm mode was nonfunctional end to end on the deploy path** (`2ea790bc`) — no vlm client variable reached the backend container and no compose file declares `env_file:`, so `ai_vlm_url` stayed `localhost` = the backend's own loopback → 100 % `verification_failed` with a NULL score while the breaker blamed the _model_. It had also silently no-oped 1.5's per-build enforcement.
4. **A search result with no score rendered a confident green "Low"** (`058ac533`).
5. **The key-frame budget counted detection rows, not stills** (`01080b51`) — one JPEG holding person+car+dog took all four slots and the UI's provenance id could name a detection the model never saw. The Hypothesis generator drew a unique `file_path` per row — the one shape no real batch has.
6. **A video container was base64'd into the prompt as `image/jpeg`** (`bdb55335`), reachable by design because the detector sets `detection_file_path = video_path` for video rows.
7. **The prompt had no context budget at all, and the only slot figure the backend carried was the WRONG one** (`d1e279fd`) — a 500-row batch is ~30 K text tokens against a 16,384-token vlm slot, graded against the _legacy_ LLM's 32,768.

**Plus the gate itself** (`13f2d65e`): `Test Coverage Gate` reddened #6681 claiming a hook had no tests. It does — at `.test.tsx`, and the JSX provider wrapper there makes `.ts` illegal, so the suite's name was not the bug. `find_test_file` built exactly one candidate from the _source's_ suffix; the repo's own comment above it had always said ".test.ts/tsx" and only the code implemented half. Fixed to try both extensions (the negative pin — a genuinely untested file still returns `None` — is kept so the gate is not neutered), reproduced red before and green after.

## 3. What failed, and why

- **Nothing shipped was reverted; nothing here is a silent pass.** The seven items above are the review's failures, all fixed and gated.
- **A background tier with a 0-byte log is not a pass** — two full-tier background runs reported exit 0 and wrote empty logs; both were discarded and the tier re-run in the foreground. The evidence is the printed summary line, not the exit code.
- **A transient xdist worker ERROR is an identity, not a green** — one appeared on a pure exception-construction test in the first foreground tier; **0** reproductions in 3 targeted repeats, 0 standalone, 0 on a clean second tier. Banked with its counts (ledger item 27).
- **The residency claim an agent reported was wrong** (item 24) and the correction is a _finding_, not a fix: `BACKEND_MODEL_PRELOAD` defaults **False**, `setup.py` enables it only _above_ a strict 24 GiB (so the 24 GB A5500 is outside its own spec figure), and `models.yml`'s `preload:` flag is parsed into `ModelConfig` and **read by nobody**. On the target hardware the re-ID handle is simply _absent_ and the leg answers "unavailable" — the correct degrade, but not "resident". Closing that is a policy decision (§4).

## 4. Decisions the owner owes

1. **The alerts family's unverified bucket** (ledger item 26). `AlertsPage`/`AlertCameraGroup` are live on `/alerts` and still carry **14** `risk_score || 0`/`?? 0` and **5** `risk_level ||` sites. Every other null-lie site was fixed at the reader; this one is a product call about what an unverified alert _contributes to a risk-count chip_, and the alerts UI has no badge slot to put the answer in. Ruled, or scoped out to Phase 3's polish — but not patched half-way.
2. **Residency policy** (item 24). Move residency from `setup.py`'s install-time VRAM guess to something the deployment declares, **or** give the boot sweep a real reader for `cfg.preload`. Either is outside M1; neither is silently patched.
3. **Video batches in the vlm path.** The refusal added in `bdb55335` is honest but it is a _gap_: a real video→frame extractor needs ffmpeg in the backend image, or `thumbnail_path` populated for video rows. Ship the refusal for M1, or fund the extractor now.
4. **Synthetic media for the 408 label-only eval items.** Nothing in M1 waits on it; **S2 and S3 cannot be measured until it exists** (item 19). This is the single item gating the bake-off's verdicts.
5. **The 8 low-expecting incidents** (deferred "ignore this for now"). The double-report stands until the owner relabels or excludes.
6. Standing, unchanged: the M2 VLM pick, go-live 3.1, any D#/S# change, dgx-inference, Brev spend, R10, postponed-roadmap items, and **merging #6681**.
