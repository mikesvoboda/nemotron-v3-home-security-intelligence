# A5500 operator handoff — start here if you are the agent driving the A5500 box

Dated 2026-09-28, written on the dev box (a brokered GB300 sandbox) for an agent
sitting on the real hardware. It claims no execution on the A5500 — everything
below is the _shape_ of the run, verified against the repo at the head named
under "What to fetch". This document is hand-written; the checklist it points at
is GENERATED (see "Two documents, two authorities").

## What this run is

The A5500 is the first 24 GB-class hardware the project has, and the spec
reserves two of its six acceptance bars to exactly that class (ledger finding
F13): **S1** peak VRAM ≤ 20.4 GiB with the whole stack resident and no CPU
offload, and **S4** p95 per-batch verdict ≤ 30 s including cold starts. Every
number this repo has today is from a 249 GiB GB300 and is _indicative only_.
The run also carries **M1's exit test** (vlm mode end-to-end with the shipped
serving VLM as the smoke model) and the two probes P0.3 requires before any
event reaches a server.

The serving VLM is **Qwen3-VL-8B-Instruct Q4_K_M** — the owner's M2 pick (spec
rev 7, ledger item 35), provisional on precisely the measurements this box
produces. The **4B pair is the named fallback** and must get its own S1 reading
in the same session: if the 8B fails S1, the pick falls to a model that already
has a number on this box, not to a re-run.

the real value; a number from a card that is not the tier's card is not that

## Boot order (a cold box, first two hours)

1. **Generate the env; do not copy the example.**
   `docs/getting-started/installation.md` forbids `cp .env.example .env`
   (placeholder credentials) and setup.py generates real ones — but the two
   docs contradict each other on this; follow setup.py. THEN apply
   `env-templates/a5500.env.template`'s deltas onto the generated `.env`:
   every `GPU_*` to 0 (single-GPU), `CUDA_ARCHITECTURES=86`,
   `AI_MODELS_PATH`, `PODMAN_SOCKET`, `TMPDIR` to a directory that exists. The
   template deliberately does NOT pin ctx/parallel, `VLM_GPU_LAYERS`,
   `VLM_REQUIRED_BUILD` or any secret — read its header before changing that.
2. **Fetch both weight pairs BEFORE the precheck.** The checklist's "Serving
   VLM" section carries all four files' byte counts and sha256s, the two
   HuggingFace repo ids, and the traps: fetch the **Q8_0** projector, never the
   F16 (an F16 serve starts fine and its hash matches nothing — the loudest
   silent failure on this run); `chmod 644` after fetching (files land mode 640
   and the container's uid 1000 dies `Permission denied` on a file you can
   read). 8.3 GB of files total. Verify on disk with `ls -l` + `sha256sum`:
   the repo's `vlm_model` check regexes the ENV STRING, so a fabricated env
   naming nonexistent files still PASSes — nothing in this repo can tell you
   the weights are missing except you.
3. **Precheck, with the right env file.**
   `uv run python scripts/a5500_precheck.py --env-file .env` — an unqualified
   run checks the _template_, not the machine. Expect the shipped `.env.example`
   defaults to FAIL GPU-assignment and CUDA-architecture until step 1 is applied
   on the copy; that is the pre-fix state the steps exist to clear. (One WARN,
   `pycache_stale`, is a dev-box artifact and will read PASS on a fresh clone.)
4. **Build — there is nothing to pull.** `ai-vlm` has no registry image
   anywhere; the box must build it:
   `podman build --build-arg CUDA_ARCHITECTURES=86 -t ai-vlm:sm86 ai/vlm`.
   Leave `LLAMA_CPP_REF` at b7972 unless you move `VLM_REQUIRED_BUILD` with it
   (the client's build check fails closed). Record image digest + `compute_cap`
   - served `/props` build_info on ONE line: the only build gate in the product
     is an arch-blind substring test, so nothing in this repo can certify your
     image except that triple taken together.
5. **Up, in the two-phase shape — never a plain up.** `backend` hard-waits on
   the retired 30B `ai-llm` via `depends_on: service_healthy`, and `--profile
vlm` does NOT exclude it (the profile resolves 20 services including
   ai-llm; one 24 GB card cannot serve both). Use the repo's own proven
   sequence: name the infra/ai services, then `--no-deps backend frontend`.
   The checklist's "No legacy LLM" section carries the exact commands and the
   reason the alternative (profile-gating ai-llm) was deliberately NOT taken.

## The measurements, in run order

All detail lives in the checklist's "Serving VLM" section; this is only the
sequencing and why:

1. **Serve the 8B pair** (`MODEL_PATH` + `MMPROJ_PATH` — a projector-less serve
   loads text-only and silently degrades everything; `GPU_LAYERS=auto`, no
   `--n-gpu-layers` reduction, `CTX_SIZE`/`PARALLEL` recorded — shipped default
   32768/2). Record the **cold load time against the 120 s healthcheck
   window** — the repo has never measured the 8B's load time and the handout
   no longer guesses.
2. **Both probes, N≥3, before anything else talks to the server.**
   `scripts/vlm_probes/enforcement.py` and `tool_calls.py`, both
   `--url http://127.0.0.1:${AI_VLM_PORT:-8098} --expect-build b7972`, run via
   `uv run` (they import httpx; bare python3 looks like a broken endpoint).
   The enforcement probe is a nonce-const JSON-grammar check — ENFORCED /
   IGNORED / INCONCLUSIVE, exit 0 only on ENFORCED — **not a refusal count**,
   and one ENFORCED is not a line (a documented finding: a single pass slipped
   an endpoint that refused 13/13). Require N≥3 consecutive ENFORCED.
3. **S1, 8B.** Peak VRAM ≤ 20.4 GiB with `ai-gateway` (detector + re-ID) +
   `ai-vlm` + `backend` ALL resident — a VLM-only peak is the engine's floor,
   not S1. Sample with `nvidia-smi --query-gpu=memory.used --format=csv -l 1`
   DURING a replay (a worst-case four-image batch, ~12.2K tokens, not an idle
   serve), and copy the engine's own `projected to use N MiB` and
   `llama_kv_cache: size =` startup lines. **The trap: `auto` spilling layers
   to CPU RAM looks healthy and posts a fake S1 pass** — record explicitly
   whether any offload happened.
4. **S4, 8B.** p95 per-batch verdict ≤ 30 s including cold starts: the replay's
   per-item latencies PLUS the first request after `--sleep-idle-seconds` PLUS
   the first request after a real restart. A warm-only sample is not S4. Also
   record the **wake time from sleep against the client's 90 s wake timeout**
   (the 8B is 2.0× the 4B's bytes to copy back; M1's assertions 2/3 are the
   wake-through-sleep check).
5. **Re-serve with the 4B pair; repeat 1/3 (S1) and the load time.** Same
   commands, `VLM_MODEL_PATH`/`VLM_MMPROJ_PATH` swapped. Expect no KV relief —
   the pairs share geometry (36 KV layers); take the KV number from this box's
   llama-server line, because the two KV figures in this repo disagree and the
   disagreement is unresolved.
6. **M1's chain, not just the readings.** synthetic still → detector-closed
   batch → vlm verdict → event + verification row → badge → notification
   decision, each link recorded with the artifact proving it (plan
   `:181`). Every fit number can pass while this chain goes unproven, and then
   M1 stays open.

The replay needs an eval store, which is NOT in git (D10). Build gen-2 on the
box from the committed corpus: corpus in-repo at `data/synthetic` (413 label
sets), stock media via `uv run python scripts/synthetic_media.py fetch`
(keyless — Wikimedia Commons, permissive-license only; default root is the
dev-box `$AGENT_GPU_DIR` path, pass `--root` explicitly), then the shipped
`build_gen2(store_dir, corpus_dir=..., stock_root=...)` driver from
`backend/evaluation/eval_store.py` (its D10 guard refuses a store dir inside
the checkout — build it OUTSIDE the repo). Expect ~426 items, 13 media-bearing;
the build fails loud if zero items carry a specialist block. The replay
incantation (measured on the dev box): `DATABASE_URL` to any _placeholder_ URL
(Settings validation needs it; the replay opens no database), `ENVIRONMENT=test
PYTHONPATH=. FOSCAM_BASE_PATH=<media root>`, and `--candidate` naming exactly
what was measured (`Qwen3VL-8B-Instruct-Q4_K_M@ai-vlm:sm86`).

**What the replay can and cannot decide on this box:** with the store the repo
has today, the S2/S3 columns are the same floor-on-grammar the bake-off report
records — the media-bearing items and the specialist-context items are
disjoint. (Another agent is generating synthetic media for the 408 labeled
items right now; if a newer corpus reaches you, great — record its generation
with your numbers.) **S1, S4, the probes and M1's chain do not depend on the
corpus at all** — those are this run's real contribution even if S2/S3 stay
exactly where they are.

  box hosts any — none should run on this box; if something else owns the GPU,
  stop.
- Editing shared probes or prod `depends_on`/"fixing" the known gaps:
  `scripts/platform-healthcheck.py` is blind to ai-vlm (probes only the
  retired service's 8091) — check `http://127.0.0.1:${AI_VLM_PORT:-8098}/props`
  directly and do not "fix" the probe mid-run; `ai-llm` stays unprofiled by
  deliberate decision (see "No legacy LLM" section). Both gaps are recorded in
  ledger item 36 with reasons.

## Privacy (D10) — the line you cannot walk back

Synthetic items and aggregate metrics only. **Real-camera imagery, labels,
snapshots and the eval store never enter git** — not the store's sqlite, not a
"just this screenshot," not a per-item dump in a report. Reports are counts and
rates. The store and media live outside the checkout (the store builder enforces
this; nothing else does), and wipe them at teardown if the box is disposable.
