## 2. The two findings the repairs produced

Both came from measuring a claim instead of trusting it, and one of them is a retraction of my own proof.

**Finding A — a budget was answering a support question (CLOSED [V], `6106ea98` + `7141cad0`).** The enforcement probe asks for the verdict schema plus a required const the prompt never mentions, at `max_tokens = 400`. A reply cut off mid-object has no const in it — the const can legally sort last in the grammar — and the fail-closed ladder filed that as `ignored`, the word reserved for a server that _accepts_ the grammar and does not enforce it. On the M2 pick that is expensive in one direction only: an under-budgeted probe can read a correctly-enforcing endpoint as a non-enforcer, so a candidate could be eliminated for a number we chose. Repair: `finish_reason`-aware triage in branch order (echoed const → enforced; 200 + a truncated stop → `inconclusive`; a _complete_ reply without the const → `ignored`), one shared stop vocabulary, `None` = "the server did not say" and never inferred as truncation. **Fail-closed is unchanged**: it still raises, still maps to `verification_failed` + a NULL score, and a pin holds that an `inconclusive` caches nothing. The assess leg's sibling (`_ASSESS_MAX_TOKENS = 700`) was _measured_ before being touched — 3 of 6 stock scenes truncate there with an object that never closes — and §6's retry re-asks the same body at the same budget, so it now raises once instead of spending breaker failures on a non-answer.

**Finding G — the enforcement gate is a per-scene coin flip (OPEN, owner-level, open issue 28).** While re-testing my own claim I found the claim was wrong, and the way it was wrong is the finding: my first "the cliff does not reproduce" run drove the probe with the _analyzer_ schema (four scalar fields) while the shipped chat probe sends the full verdict **wire** schema. Re-measured with the client's own `_wire_schema()`, at the shipped 400 the same request echoes the nonce **3 of 4 times** on one scene (0/4 on another; 4/4 at 700). A scene at the cliff plus the gate's once-per-client cache means a run's enforcement verdict depends on which image happened to be first. The breaker half of it is closed by `7141cad0` and verified on the GPU with one client and no breaker reset — the shape finding B established as the real one: `breaker_open_after false`, `any_no_io_refusal false` in **both** probe arms, every scene answering with its own cause. The enforcement cliff itself still refuses 5/6 at the shipped budgets, which is the half the owner owns.

**And one measurement-discipline finding, in passing.** The ledger sentence that asserted finding A's sibling "production hits this identically" was itself an inference; the sentence is retracted in its own row and replaced with the 3-of-6 measurement. Both the bakeoff report's forward reference and finding A's row now carry the retraction.
